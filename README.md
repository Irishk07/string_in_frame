## frame_res.asm
Если вы хотите напечатать свою строку в красивой рамке на экране, то это программа для вас!

### В качестве параметров, помимо самой строки, можно указать:
* Цвет выводимой строки - по умолчанию F4h;
* Цвет рамки - по умолчанию 0Ch;
* Цвет заливки экрана - по умолчанию 05h;
* Номер рамки из дефолтных рамок (1 - 3) или 0, если хочешь задать свою рамку (в этом случае нужно перечислить 9 символов для рамки) - по умолчанию 3;
* Строка вводится после всех желаемых параметров - по умолчанию также выведется сообщение;

### Дефолтные рамки:
* Рамка 1
```
frame_res.com 4F 0C 03 1 Have a nice day
```
![Рамка 1](frames/frame1.png)
* Рамка 2 
```

```
![Рамка 2](frames/frame2.png)
* Рамка 3 
```

```
![Рамка 3](frames/frame3.png)

## keyboard.asm

Резидентная программа для DOS, которая выводит на экран в красивой рамочке значения регистров процессора при нажатии клавиши F11 и возвращает экран в прежний вид при нажатии F12.

### Преимущества:
* Вывод значений 13 регистров: CS, IP, SP, AX, BX, CX, DX, SI, DI, BP, SS, DS, ES;
* Корректное восстановление содержимого экрана;
* Работает как резидент (остается в памяти);
* Благодаря таймеру, после нажатия клавиши F11 регистры обновляются в режиме реального времени.

### В качестве параметров можно указать:
* Цвет выводимой строки - по умолчанию 4Fh;
* Цвет рамки - по умолчанию 0Ch;
* Номер рамки из дефолтных рамок (1 - 3) или 0, если хочешь задать свою рамку (в этом случае нужно перечислить 9 символов для рамки) - по умолчанию 1.

### Дефолтные рамки:

        in al, 60h
        cmp al, 01h         ; esc         
        je  @@done

        mov ax, 1111h
        mov bx, 2222h
        mov cx, 3333h
        mov dx, 4444h
        mov si, 5555h
        mov di, 6666h

        jmp @@loop
```

```
test_res.com

## Hack you

В качестве программы для взлома мне были предложены две программы: hack1.com и hack2.com - это программы, запрашивающие пароль и выводящие "Access granted" в случае успешного ввода и "Access denied" в случае ошибки.

Мне было необходимо, не изменяя бинарник, заставить программу вывести "Access granted" на неправильно введенный пароль.

Для поиска уязвимых мест я использовала дизассемблер IDA (в 16битном режиме).

### hack1.com

Внимательно проанализировав дизассемблер, я нашла уязвимость в виде переполнения буффера 

Логика программы предполагает следующее: 
* считывается пароль, введенный пользователем: для этого вызывается встроенная функция 3F (ограничение на считывание FFh байт). Полученный пароль записывается в буффера;
* полученный пароль и корректный пароль (которые лежат в памяти) хэшируются: вызывается дважды одна и та же функция, ее результаты помещаются в регистры и сравниваются;
* на основе сравнения выдается "Access granted" или "Access denied".

Буффер для пароля пользователя очень маленький: всего 10 символов; а сразу за ним в памяти лежит корректный пароль. Это можно понять по строкам дизассемблера:
```
mov 3Fh           <- функция считывания пароля
...
mov dx, 154h      <- буффер для пользовательского пароля

...

mov si, 154h     <- хэширование пользовательского пароля
call ...    

...

mov si, 15Eh    <- хэширование корректного пароля
call ...

...

mov ah, 9
mov si, 17Ah    <- печать отвергания пароля

...

mov ah, 9
mov si, 168h    <- печать принятия пароля

...
```
Из анализа этих строк делаем вывод, что буффер для пользовательского пароля лежит по адресу 54h в дизассемблированной программе (т.к. в начале кода прописано 100h -> надо вычесть 100h из адреса в метке), корректный пароль - по адресу 5Eh, а с адреса 68h лежат сообщения для пользователя. 

Итого на хранение пользовательского пароля выделено 10 байт, корректный пароль занимает также 10 байт. И корректный пароль в памяти лежит сразу после буффера для пароля пользователя! Соответственно можно так переполнить буффер для пароля, что перепишется корректный пароль и хэши совпадут: а именно 9 любых символов + \$ + 9 тех же самых символов + \$, так как видно из функции хэша, что строка хэшируется до символа \$. 

То есть главной проблемой является то, что в памяти явно лежит корректный пароль, и он хэшируется только после ввода пароля пользователем. Для устранения этой проблемы нужно хранить сам хэш, причем до буффера для пользовательского пароля, а также проверять переполнение буффера (для этого достаточно при вызове 3F поставить cx = 10d).

По этой логике я ввела пароль:
```
AAAAAAAA$AAAAAAAA$
```
Мне выдало "Access granted", хотя этот пароль не является верным. Следовательно, взлом удался!


### hack2.com

Логика этой программы предполагает следующее: 
* вызов функции проверки пароля;
* выделение на стэке области из 10 байт для записи туда пароля;
* считывается пароль, введенный пользователем: для этого вызывается встроенная функция 3F (ограничение на считывание FFh байт). Полученный пароль записывается в выделенную область стэка;
* вычисляется хэш введенного пароля;
* сравнение полученного хэша и сохраненного в памяти (по адресу 1B3h);
* на основе сравнения выдается ax выставляется в 0 или 1 и выполняется возврат из функции;
* далее проверяется значение ax и на основе него осуществляется прыжок на одну из веток, где уже выполняется вывод "Access granted" или "Access denied".

То есть на хранение пароля снова выделено 10 байт, но уже в стэке, в в котором хранятся важные данные (например, адрес возврата), соответственно при переполнении буффера можно изменить некоторые данные в стэке на те, которые нужны именно мне: достаточно ввести 12 любых символов + два символа, ASCII-коды которых будут являться адресом возврата (12, т.к. помимо буффера из 10 символов в стэке хранится еще bp). В дизассемблере видно, что нужно после функции вернуться на адрес F0h, так как там происходит печать сообщения, что пароль принят, но так как у нас прописано org 100h, то необходимо еще прибавить 100h и получим адрес: 010Fh.

```
...

mov ah, 9       <- адрес 000Fh
mov dx, 190h    <- печать принятия пароля
int 21h

...

-func-:
        ...

        sub sp, 0Ah     <- 10 байт для буффера на стэке

        ...

        cmp al, 1B3h    <- сравнение с верным хэшом по адресу 1B3h

        ...

        xor ax, ax      <- ax = 0, если неверно

        ...

        mov ax, 1       <- ax = 1, если верно

        ...

        ret

...
```

Итого главной проблемой является то, что в стэке выделяется место для хранения буффера и никак не проверяется то, что пользователь ввел данных больше, чем 10d. Для устранения этой проблемы нужно проверять переполнение буффера, чтобы в стэке не затирались важные данные (для этого достаточно при вызове 3F поставить cx = 10d).

Исходя из всего этого я ввела пароль:
```
AAAAAAAAAAAA?? 
```
Для получения последних символов: alt+15 и alt+1, шестнадцатиричный код равен 0F и 01 (порядок байт little-endian, поэтому сначала 0F, потом 01).

Мне выдало "Access granted", хотя этот пароль не является верным. Следовательно, взлом удался!

## Hack me

Если ты тоже хочешь попробовать себя в роли хакера, то скачивай файлы **crackme_easy.com** и **crackme_hard.com**: первый содержит вполне очевидную уязвимость, а для взлома второго придется немного напрячься

Запуск программы:
```
crackme_easy.com
```
Выведется строка
```
Please, enter the password:
```
После чего необходимо ввести пароль и нажать Enter

Для тестирования удобно использовать:
```
crackme_easy.com < pass.txt
```
В таком случае не надо каждый раз вводить пароль в терминал, можно просто использовать перенаправление ввода, записав пароль в файл

*В случае сложностей попробуй поразмышлять на тему переполнения буффера и перезаписывания данных в стэке*
